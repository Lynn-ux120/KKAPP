# 2026-10-04 第五轮改造：修凝视掉帧 + 提清晰度

## 用户诉求

「在触发班主任的凝视之后还是很卡，清晰度不够，需要往上提」——
两个诉求方向相反（要更清晰 = 更多像素 = 更慢），必须先找出可回收的浪费。

## 定位过程（都用 software 渲染后端 + dummy 驱动复现最坏情况）

写了三个基准脚本：

- `tools/bench_render.py` —— 凝视开销分解 + `RENDER_SCALE` 倍率扫描
- `tools/bench_flip.py` —— flip 缩放成本 vs 画布尺寸 / 滤波质量
- `tools/bench_tint.py` —— 凝视红罩几种实现方式的成本对比

关键测量结论：

1. **凝视态额外开销 +1.45 ms**，其中**整屏 SRCALPHA 红罩占 0.65 ms**
   （`overlay_gaze` 全画布 alpha 混合），是凝视态最贵的一步。
2. **路面标线 0.23 ms** —— 把三条跑道合成一张画布宽的 Surface，
   每次 blit 都要遍历整行透明像素，绝大部分是空的。
3. **`display.flip()` 是大头（4~5 ms）**，且随画布像素线性增长。
   带 `FULLSCREEN` 时比不带贵约 3 倍（要缩放到真实输出尺寸）。
   `bench_flip.py`：720×1600 → 0.85 ms，1080×2400 → 2.94 ms（非全屏）。
4. **`fill(BLEND_RGB_ADD)` 整屏加法 5.31 ms**，比 alpha blit 还慢 8 倍，
   绝对不能用来做全屏染色。

## 做的改动

### 性能

- **凝视红罩 → 预烘红版背景**：`_make_gaze_variant()` 在 `_step_world` 里
  生成一张 `bg_gaze`，`draw_background()` 按 `self.gaze` 换图 blit。
  0.65 ms → 0.16 ms；凝视额外开销 **+1.45 ms → ≈+0.3 ms**。
  代价：人物/障碍不再被染色（alpha 只有 26/255，肉眼几乎无差）。
- **路面标线改窄条平铺**：`_build_road_marks()` 只做"一条跑道一节"
  （`px(8)` × `px(26)`）的窄条，`draw_road_marks()` 每行对三个跑道中心各 blit 一次。
  0.23 ms → **0.03 ms**。
- **辉光文字合成缓存**：`draw_glow_text()` 原先是 9 次叠加 blit，
  改成把"描边+主文字"预合成一张 Surface 缓存，运行时 1 次 blit。
  开始界面标题每帧都在用它。
- 删掉不再需要的 `self.overlay_gaze`（省 1.8M×4B 显存）。

### 清晰度：把 `_S` 恢复成真正的渲染倍率

**这是本轮最重要的结构改动。** 第四轮为了性能把 `_S` 钉死成 1，
`px()` 退化成 `round()`，于是所有排版数值都写死在"720 宽"的语义里，
一提高分辨率人物和字号就会相对变小、布局全乱。

现在：

```python
BASE_W = 720                      # 设计稿基准宽
BASE_H = 820                      # 设计稿基准高
RENDER_SCALE = float(os.environ.get("KK_RENDER_SCALE", "1.25"))
_S = RENDER_SCALE
DESIGN_W = round(BASE_W * _S)     # 画布实际宽（900）
DESIGN_H = round(BASE_H * _S)     # 画布默认高（1025）
CANVAS_H_MIN/MAX = round(820/1800 * _S)
def px(v): return int(round(v * _S))     # 唯一换算出口
```

`RENDER_SCALE = 1.25` → 画布 900 宽，1080 屏上只放大 1.20×（原来 1.50×）。

### 踩到的坑（`test_screen_fit.py` 抓到）

`_apply_render_scale` 里速度换算的分母用了 `DESIGN_H`（= `BASE_H × _S`），
把 `_S` 约掉了 → **提高清晰度后障碍下落同比变慢 25%**（预警时间从 3.31s 变 4.14s）。
`DESIGN_SPEEDS` 单位是"设计稿像素/秒"，正确分母是 `BASE_H`：

```python
r = HEIGHT / BASE_H     # 不是 HEIGHT / DESIGN_H
```

修好后预警时间恢复 3.31s、难度漂移 3.5%。

## 给用户的话

`RENDER_SCALE` 是唯一旋钮：真机仍掉帧就调小（1.0），觉得不够锐就调大（1.5，
1080 屏 1:1 最锐但像素 2.59M）。改一个常数即可，布局代码不用动。
临时试数值可走环境变量 `KK_RENDER_SCALE`。
