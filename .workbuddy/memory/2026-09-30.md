### 1) 清晰度：从"小画布放大"改为"原生分辨率渲染"

**旧做法**（上一轮）：画布固定 720 宽，按屏幕比例加高 → SCALED 放大 1.5~2.8 倍，
等于把 720p 的画面强行放大，画面糊。

**新做法**：画布宽度直接对齐屏幕物理宽度。

```
scale    = 屏幕宽 / 720
逻辑画布 = (720 × scale, 屏幕高 × scale)   # 与屏幕 1:1
```

配合 `pygame.SCALED` 就是 **1.00 倍原生渲染**，主流机型（1080×2400 / 1170×2532 /
1080×2520）不再有任何放大。实测各机型放大倍数与黑边见 `tools/test_screen_fit.py`。

**关键**：引入全局渲染缩放因子 `_S`（= scale）和 `px(v)` 换算函数，所有写死的像素
尺寸/字号/间距都改成 `px(...)`；新增 `_apply_render_scale(scale, canvas_h)`
在启动时统一重算 WIDTH/HEIGHT/PLAY_W/SIDE_W/字体基准等。

**性能上限**：软件渲染下像素越多越吃力，设 `MAX_CANVAS_PIXELS`（约 300 万，
相当于 1080×2400）封顶。2K/平板超出时按 √k 整体降采样（不是只降高），
保证宽高比不变、黑边仍为 0。2K 机型 1.20 倍、平板 1.32 倍。

### 2) 流畅度：渲染路径全量预渲染 + 缓存

软件渲染下**每帧新建 Surface 是最贵的开销**。改动清单：

| 对象 | 做法 |
| --- | --- |
| 背景、跑道分隔线 | 预渲染整张 Surface |
| 路面标线 | 预渲染一格后垂直平铺（省掉每帧几十次 draw.rect） |
| 侧边栏静态部分 | 预渲染整张 |
| 开始/结束/凝视 半透明遮罩 | 预渲染复用（原来每帧全屏新建 SRCALPHA Surface） |
| 文字 | `_text_cache` 按 (文本, 字号, 颜色) 缓存渲染结果 |
| 椭圆阴影 | `_shadow_cache` / `_shadow_cache2` 按尺寸缓存 |
| 道具光晕 | `_glow_cache` 缓存 |
| 按钮面板 / 悬停 / 光晕 / 按下态 | 全部预渲染并缓存 |

实测 `tools/test_perf.py`（无头软件渲染，最坏情况）：
```
主流 1080x2400   5.08 ms/帧  ≈197 FPS
2K   1440x3200   6.09 ms/帧  ≈164 FPS
```
60 FPS 预算 16.7 ms/帧，余量 3 倍。

**可用做法**（两步式，已验证）：
```powershell

$req.Headers.Add("Authorization", "Bearer $token")   # 注意：Accept 是受限头，
$req.Accept = "application/vnd.github+json"          # 必须用属性赋值，不能用 Headers.Add
$req.UserAgent = "probe"
$req.AllowAutoRedirect = $false
$resp = $req.GetResponse(); $loc = $resp.Headers["Location"]; $resp.Close()
Invoke-WebRequest -Uri $loc -OutFile $zip -TimeoutSec 300   # 重定向地址带签名，无需再带 token
```

## 第四轮改造：修掉帧 / 修全屏 / 移除侧栏 / 换图标与加载背景

用户真机反馈："掉帧现象非常明显"、"界面依旧无法撑满全屏"。

### 1) 掉帧根因（重要，别再犯）

上一轮为了"原生清晰度"把画布放大到**屏幕物理分辨率**（1080×2400 ≈ 260 万像素）。
但 **pygame 是 CPU 软件渲染**，画布面积直接等于每帧要写入的像素量——
背景 1 次全屏 blit + 路面标线二十来次平铺 + 侧边栏 + 遮罩，每帧近千万像素。
手机必然掉帧。**"提高清晰度"和"软件渲染"是互斥的，画布越大越卡。**

**修法**：画布宽固定 **720**，高按屏幕比例 → 主流机型 720×1600 ≈ **115 万像素**
（原来的 44%），绘制量降到 1/3。清晰度交给 `pygame.SCALED` 的 GPU 缩放。

新增 `tools/profile_frame.py` 做逐帧耗时分解，实测（1080×2400）：

| 环节 | 耗时 |
| --- | --- |
| 背景 blit | 0.67 ms |
| 路面标线 | 0.20 ms |
| 顶部 HUD | 0.12 ms |
| 全部角色/障碍/粒子 | 0.21 ms |
| **SDL 缩放输出 flip** | **4.20 ms** ← 大头，走 GPU 后不占 CPU |

结论：绘制只占 ~1.2ms，**输出缩放才是大头**。若真机仍掉帧，说明设备回退到了
软件 renderer，唯一办法是把 `DESIGN_W` 再调小。

### 2) 撑不满全屏的根因

`pygame.SCALED` 默认是 **letterbox**（保持宽高比 + 填黑边）——这才是"撑不满"的
元凶，跟画布尺寸无关。修法两条：

1. `os.environ.setdefault("SDL_RENDER_LOGICAL_SIZE_MODE", "overscan")`
   必须在建窗**之前**设，SDL 会直接拉伸铺满。
2. 画布宽高比 = 屏幕宽高比，这样拉伸无形变。

尺寸探测失败时自动退回 letterbox（画布是设计稿比例，留黑边好过拉变形）。
探测顺序也重写了：`get_desktop_sizes()` → `get_desktop_size()` → 全屏探窗，
返回 `(0,0)` 表示失败；**删掉了 `pygame.display.Info()` 那一支**（没建窗口时
current_w/h 是 0 或假值，会误导）。

### 3) 移除右侧键位说明栏

- `PLAY_W` 现在 = `WIDTH`（跑道铺满全宽），`SIDE_PANEL_W = 0`
- 删掉 `_build_side_panel_static` / `draw_side_panel`
- 状态信息全部搬到**顶部横条** `draw_hud`：得分（金色大字）/ 最高分 / 时间 /
  凝视倒计时全宽进度条 / 无敌与加速剩余时间；配 `_build_hud_backdrop()` 预渲染
  的渐变压暗条保证可读
- 障碍加宽 104 → `OBSTACLE_W = 150`，道具 52 → `POWERUP_SIZE = 76`
  （跑道变宽了，不调会显得空旷）
- 追击者名字从**头顶**移到**脚下**（`feet_y + 5`，`base_feet_y = HEIGHT - 44`）——
  追击者贴在玩家两侧，名字放头顶会被玩家挡住

### 4) 操作与规则提醒前移到开始界面

新增 `_draw_start_help()`：开始按钮下方一块玻璃面板，左右两栏
「操作方式」（换道/跳跃的键盘键 + 触屏手势）和「游戏规则」（障碍类型、
凝视机制、道具效果）。所有纵向位置改用 `vh(fraction)`（按画布高度比例），
这样 820~1800 的画布高度都能自适应，不会溢出。

### 5) 换图标与加载背景

- 新增 `tools/prep_assets.py`：把 `kkphoto.png`（图标源）和 `beijing.png`
  （加载背景源）**右下角的「千问」水印抹掉**，输出 `icon.png`(512×512) 和
  `loading_bg.png`。去水印用**拉普拉斯平滑**（以矩形四周边界为条件向内部迭代
  扩散 24 次），背景是平滑渐变所以看不出痕迹。
  水印矩形：kkphoto `(866,912,1012,994)`、beijing `(600,1208,714,1276)`。
- `buildozer.spec`：`presplash.filename` 也换成 `loading_bg.png`
  （Android 闪屏 → 游戏内加载界面 同图无缝衔接）；
  新增 `source.exclude_patterns = kkphoto.png,beijing.png`（素材源图不打进 APK）。
- **加载背景比例坑**：源图 720×1280（9:16），画布多在 20:9。三种处理都试过：
  - 按宽度铺 + 底部填色块 → 源图底部是**亮色铁轨**，填出来的色带留一道明显分界 ✗
  - 按高度铺满裁切（cover）→ **标题被裁掉左右各 2%** ✗
  - ✅ **按宽度铺 + 把图片最下缘 72px 纵向拉伸补齐** → 像隧道向远处延伸，几乎无痕

### 6) 其他

- `_render_text` 的文字缓存改为 **LRU**（`OrderedDict` + `popitem(last=False)`）。
  原来"满 600 条就整体 clear"，而得分/时间这类每帧都在变的文本会不断产生新条目，
  清空会让所有静态文案一起重渲染 → **周期性掉帧尖峰**。
- 路面标线 tile 只做**标线本体 26px** 而非整段 78px 间隔，少处理 2/3 透明像素。
- 判定线（`PLAYER_Y + 8`）颜色调暗 `(100,110,148)`、宽度 4→3px，
  因为它横穿追击者身体显得像压在身上的横杠。
- 删除 `tools/gen_icon.py`（图标改由 `prep_assets.py` 生成，避免两个脚本打架）。
- 新增 `vh(fraction)` 布局辅助函数。
